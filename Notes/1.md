# How Does Java Work?

Java is designed to be **platform-independent**, which means that Java programs can be written once and run on different operating systems.

The key component that makes this possible is the **JVM (Java Virtual Machine)**.

## 1. Java and the JVM

A typical Java execution environment can be understood as:

```text
Hardware
   ↓
Operating System (OS)
   ↓
JVM (Java Virtual Machine)
```

The **JVM runs on top of the operating system**.

Java is platform-independent, but the **JVM itself is platform-dependent**.

For example:

* Windows has a JVM designed for Windows.
* Linux has a JVM designed for Linux.
* macOS has a JVM designed for macOS.

However, the Java bytecode remains the same.

## 2. What Does the JVM Understand?

The JVM does **not directly understand Java source code**.

Java source code is written in a `.java` file:

```text
HelloWorld.java
```

The Java compiler converts this source code into **bytecode**.

```text
Java Source Code
      ↓
    Compiler
      ↓
    Bytecode
      ↓
     JVM
      ↓
    Output
```

The bytecode is stored in a file with the `.class` extension:

```text
HelloWorld.java
       ↓
   Compiler
       ↓
HelloWorld.class
```

The `.class` file contains the bytecode that the JVM can execute.

## 3. How Does Java Execute?

Suppose we have the following Java program:

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello World");
    }
}
```

When we compile the program, the Java compiler converts the `.java` file into bytecode:

```text
HelloWorld.java
      ↓
    javac
      ↓
HelloWorld.class
```

When we run the program, the JVM loads and executes the bytecode.

The JVM looks for the `main()` method, which serves as the **entry point** for a standard Java application.

```text
.java file
    ↓
Java Compiler
    ↓
.class file (Bytecode)
    ↓
JVM
    ↓
main() method
    ↓
Program execution
    ↓
Output
```

## 4. When Is the Bytecode Created?

The bytecode is created when the Java source code is **compiled**, not simply because we click "Run."

For example:

```bash
javac HelloWorld.java
```

This generates:

```text
HelloWorld.class
```

Then we can execute it using:

```bash
java HelloWorld
```

So:

| File     | Purpose                |
| -------- | ---------------------- |
| `.java`  | Java source code       |
| `.class` | Compiled Java bytecode |

## 5. What Is JRE?

Now the question is:

> How does the JVM run a Java program?

The **JRE (Java Runtime Environment)** provides the environment required to run Java applications. It includes the JVM along with the runtime libraries and supporting components needed for execution.

A simplified relationship is:

```text
JRE
 ├── JVM
 └── Java Runtime Libraries
```

## 6. What Is JDK?

The **JDK (Java Development Kit)** is used to develop Java applications.

It contains the tools required to write, compile, and run Java programs. It includes the JRE components, including the JVM and runtime libraries.

A simplified view is:

```text
JDK
 └── JRE
      ├── JVM
      └── Runtime Libraries
```

> **Note:** This JDK → JRE → JVM diagram is a useful conceptual model. In modern Java distributions, the JDK and runtime packaging is more nuanced, and the JRE is not generally distributed as a separate product.

## 7. Why Is Java Platform Independent?

Java follows the concept:

> **WORA — Write Once, Run Anywhere**

The basic idea is:

```text
Java Source Code
       ↓
     Compiler
       ↓
    Bytecode
       ↓
 ┌─────┼─────┐
 ↓     ↓     ↓
JVM   JVM   JVM
Win   Linux macOS
```

The same Java bytecode can run on different operating systems as long as a compatible JVM is available for that platform.

This is why Java is commonly described as **platform-independent**, while the JVM is **platform-dependent**.

## Summary

The overall process can be summarized as:

```text
Java Source Code (.java)
          ↓
       Compiler
          ↓
    Bytecode (.class)
          ↓
         JVM
          ↓
    Program Execution
          ↓
        Output
```

And the Java platform can be conceptually represented as:

```text
JDK
 ↓
JRE
 ↓
JVM
 ↓
Executes Bytecode
```

### Key Points

* Java source code is stored in `.java` files.
* The Java compiler converts `.java` source code into bytecode.
* Bytecode is stored in `.class` files.
* The JVM executes the bytecode.
* The `main()` method is the entry point for a standard Java application.
* Java is platform-independent because the same bytecode can run on JVMs built for different platforms.
* The JVM itself is platform-dependent.
* **WORA** means **Write Once, Run Anywhere**.
