# Method Overloading, Method Overriding, and Memory

Now that we understand classes, objects, methods, stack, and heap, let's understand two important OOP concepts:

* Method Overloading
* Method Overriding

We will also understand:

* What happens in Stack and Heap memory
* Getters and Setters
* Class Overloading and Class Overriding

---

# 1. Method Overloading

**Method overloading** means having multiple methods with the **same name but different parameter lists** in the same class.

For example:

```java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }

    double add(double a, double b) {
        return a + b;
    }
}
```

Here, all methods are called `add`, but their parameters are different.

```text
add(int, int)
add(int, int, int)
add(double, double)
```

This is **method overloading**.

---

# 2. Why Do We Use Method Overloading?

Suppose we didn't have method overloading.

We might need different method names:

```java
addTwoNumbers(10, 20);

addThreeNumbers(10, 20, 30);

addDecimalNumbers(10.5, 20.5);
```

With method overloading, we can use the same meaningful method name:

```java
add(10, 20);

add(10, 20, 30);

add(10.5, 20.5);
```

Java determines which method should be called based on the arguments.

---

# 3. How Does Java Decide Which Overloaded Method to Call?

Consider:

```java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}
```

Now:

```java
Calculator calculator = new Calculator();

calculator.add(10, 20);
```

Java sees:

```text
add(10, 20)
     ↓
2 arguments
     ↓
add(int, int)
```

And:

```java
calculator.add(10, 20, 30);
```

Java sees:

```text
add(10, 20, 30)
       ↓
3 arguments
       ↓
add(int, int, int)
```

---

# 4. Rules for Method Overloading

Methods can be overloaded by changing:

### Number of Parameters

```java
void display(int a) {
}

void display(int a, int b) {
}
```

### Type of Parameters

```java
void display(int a) {
}

void display(double a) {
}
```

### Order of Parameters

```java
void display(int a, double b) {
}

void display(double a, int b) {
}
```

However, **changing only the return type is not enough**.

This is invalid:

```java
int add(int a, int b) {
    return a + b;
}

double add(int a, int b) {
    return a + b;
}
```

The parameter lists are identical, so Java cannot distinguish these methods based only on the return type.

---

# 5. Method Overloading and Memory

Let's understand what happens when we call an overloaded method.

Consider:

```java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}

public class Main {

    public static void main(String[] args) {

        Calculator calculator = new Calculator();

        int result = calculator.add(10, 20);
    }
}
```

When the program runs, conceptually:

```text
STACK                         HEAP
─────                         ────

main() frame

calculator ───────────────→  Calculator Object
result = 30
```

The `calculator` variable is a reference to the object.

The `Calculator` object is allocated on the heap.

When:

```java
calculator.add(10, 20);
```

is called, a new stack frame is created for that method invocation.

```text
STACK

┌─────────────────────────────┐
│ add(int, int)               │
│ a = 10                      │
│ b = 20                      │
│ return value = 30           │
├─────────────────────────────┤
│ main()                      │
│ calculator → object         │
│ result                      │
└─────────────────────────────┘

             │
             ↓

HEAP

┌─────────────────────────────┐
│ Calculator Object           │
└─────────────────────────────┘
```

After `add()` finishes, its stack frame is removed.

```text
STACK

┌─────────────────────────────┐
│ main()                      │
│ calculator → object         │
│ result = 30                 │
└─────────────────────────────┘
```

# 6. Method Overriding

**Method overriding** occurs when a subclass provides its own implementation of an inherited instance method from its superclass.

For example:

```java
class Animal {

    void sound() {
        System.out.println("Animal makes a sound");
    }
}

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}
```

Here:

```text
Animal
  ↑
  │
 Dog
```

`Dog` inherits from `Animal`.

Both classes have a `sound()` method.

The `Dog` implementation **overrides** the inherited `sound()` method.

---

# 7. Calling an Overridden Method

```java
public class Main {

    public static void main(String[] args) {

        Dog dog = new Dog();

        dog.sound();
    }
}
```

Output:

```text
Dog barks
```

The `Dog` version of `sound()` is executed.

---

# 8. Runtime Polymorphism

Overriding becomes especially important when we use a parent-class reference to refer to a child object.

```java
Animal animal = new Dog();

animal.sound();
```

Output:

```text
Dog barks
```

Even though the reference type is:

```text
Animal
```

the actual object is:

```text
Dog
```

The overridden instance method is selected at runtime based on the actual object.

This is called **runtime polymorphism** or **dynamic method dispatch**.

---

# 9. Stack and Heap During Method Overriding

Consider:

```java
Animal animal = new Dog();
```

Conceptually:

```text
STACK                         HEAP
─────                         ────

animal ───────────────────→  Dog Object
```

The reference variable `animal` is associated with the `main()` stack frame.

The `Dog` object is allocated on the heap.

Now:

```java
animal.sound();
```

A stack frame is created for the method invocation.

```text
STACK

┌─────────────────────────────┐
│ Dog.sound()                 │
├─────────────────────────────┤
│ main()                      │
│ animal → Dog object         │
└─────────────────────────────┘

              │
              ↓

HEAP

┌─────────────────────────────┐
│ Dog Object                  │
│                             │
│ overridden sound()          │
└─────────────────────────────┘
```

After `sound()` finishes:

```text
STACK

┌─────────────────────────────┐
│ main()                      │
│ animal → Dog object         │
└─────────────────────────────┘
```

The method's stack frame is removed.

---

# 10. Overloading vs Overriding

This is one of the most important differences to remember.

| Feature       | Overloading                                | Overriding                                               |
| ------------- | ------------------------------------------ | -------------------------------------------------------- |
| Meaning       | Same method name, different parameter list | Subclass provides new implementation of inherited method |
| Classes       | Usually within the same class              | Requires inheritance                                     |
| Parameters    | Must differ                                | Must match the overridden method's signature             |
| When selected | At compile time                            | At runtime for overridden instance methods               |
| Main concept  | Compile-time polymorphism                  | Runtime polymorphism                                     |
| Example       | `add(int,int)` and `add(int,int,int)`      | `Dog.sound()` overriding `Animal.sound()`                |

### Easy Way to Remember

```text
OVERLOADING
Same class
Same method name
Different parameters

OVERriding
Parent → Child
Same method signature
Child provides implementation
```

# 11. Can Classes Be Overloaded?

Strictly speaking, **classes are not overloaded in Java in the same sense that methods are**.

You can have multiple classes with different names:

```java
class Car {
}

class Bike {
}
```

But this is not called class overloading.

However, there is a concept that is sometimes confused with "class overloading":

## Constructor Overloading

A class can have multiple constructors with different parameter lists.

For example:

```java
class Student {

    String name;
    int age;

    Student() {
        System.out.println("Default constructor");
    }

    Student(String name) {
        this.name = name;
    }

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

Now we can create objects in different ways:

```java
Student s1 = new Student();

Student s2 = new Student("Rahul");

Student s3 = new Student("Rahul", 20);
```

This is called **constructor overloading**, not class overloading.

---

# 12. Can Classes Be Overridden?

A class itself cannot be overridden.

**Methods can be overridden.**

For example:

```java
class Animal {

    void sound() {
    }
}

class Dog extends Animal {

    @Override
    void sound() {
    }
}
```

Here:

```text
Animal
  ↓
Dog
```

The `sound()` method is overridden.

The `Animal` class is not overridden.

# 13. Getters and Setters

Now let's understand another important concept.

Suppose we have:

```java
class Student {

    String name;
    int age;
}
```

We can directly access the fields:

```java
Student student = new Student();

student.name = "Rahul";
student.age = 20;
```

But in object-oriented programming, fields are often made `private` and accessed through **getters and setters**.

---

# 14. Why Use Getters and Setters?

Consider:

```java
class Student {

    private String name;
    private int age;
}
```

Now this won't work from outside the class:

```java
student.name = "Rahul";
```

because `name` is `private`.

Instead, we provide methods to access and modify the fields.

These methods are commonly called:

```text
Getter → Gets/returns a value
Setter → Sets/changes a value
```

---

# 15. Getter

A getter is a method used to retrieve a field's value.

Example:

```java
public String getName() {
    return name;
}
```

For age:

```java
public int getAge() {
    return age;
}
```

---

# 16. Setter

A setter is a method used to modify a field's value.

Example:

```java
public void setName(String name) {
    this.name = name;
}
```

For age:

```java
public void setAge(int age) {
    this.age = age;
}
```

---

# 17. Complete Getter and Setter Example

```java
class Student {

    private String name;
    private int age;

    // Getter
    public String getName() {
        return name;
    }

    // Setter
    public void setName(String name) {
        this.name = name;
    }

    // Getter
    public int getAge() {
        return age;
    }

    // Setter
    public void setAge(int age) {
        this.age = age;
    }
}
```

Now we can use the class:

```java
public class Main {

    public static void main(String[] args) {

        Student student = new Student();

        student.setName("Rahul");
        student.setAge(20);

        System.out.println(student.getName());
        System.out.println(student.getAge());
    }
}
```

Output:

```text
Rahul
20
```

---

# 18. Why `this` Is Used in Setters

Look at:

```java
public void setName(String name) {
    this.name = name;
}
```

There are two `name`s here.

```text
this.name
    ↑
Object's instance variable

name
 ↑
Method parameter
```

So:

```java
this.name = name;
```

means:

```text
Object's name = parameter name
```

For example:

```java
student.setName("Rahul");
```

During the method call:

```text
this.name → Student object's field
name      → "Rahul"
```

So the assignment becomes:

```text
student.name = "Rahul"
```

---

# 19. Getters, Setters, and Encapsulation

Getters and setters are commonly used as part of **encapsulation**.

Instead of allowing direct access:

```java
student.age = -100;
```

we can control how the value is changed:

```java
public void setAge(int age) {

    if (age >= 0) {
        this.age = age;
    }
}
```

Now:

```java
student.setAge(-100);
```

will not update the field.

This gives the class control over its internal state.

---

# 20. Stack and Heap — Complete Picture

Let's combine everything with a simple example.

```java
class Student {

    private String name;
    private int age;

    public void setName(String name) {
        this.name = name;
    }

    public String getName() {
        return name;
    }
}

public class Main {

    public static void main(String[] args) {

        Student student = new Student();

        student.setName("Rahul");

        System.out.println(student.getName());
    }
}
```

When `main()` starts:

```text
STACK

┌─────────────────────────┐
│ main()                  │
│                         │
│ student ────────────────┼───────┐
└─────────────────────────┘       │
                                  ↓
                                HEAP

                         ┌─────────────────┐
                         │ Student Object  │
                         │                 │
                         │ name = "Rahul"  │
                         │ age = 0         │
                         └─────────────────┘
```

When:

```java
student.setName("Rahul");
```

is called:

```text
STACK

┌─────────────────────────────┐
│ setName()                   │
│ this → Student object       │
│ name → "Rahul"              │
├─────────────────────────────┤
│ main()                      │
│ student → Student object    │
└─────────────────────────────┘

              │
              ↓

HEAP

┌─────────────────────────────┐
│ Student Object              │
│ name = "Rahul"              │
│ age = 0                     │
└─────────────────────────────┘
```

After `setName()` finishes, its stack frame disappears.

```text
STACK

┌─────────────────────────────┐
│ main()                      │
│ student → Student object    │
└─────────────────────────────┘

              │
              ↓

HEAP

┌─────────────────────────────┐
│ Student Object              │
│ name = "Rahul"              │
│ age = 0                     │
└─────────────────────────────┘
```

Then:

```java
student.getName();
```

creates another stack frame for `getName()`.

The method reads the object's field from the heap and returns the value.

---

# 21. Is `main()` Stored in the Stack?

This is a common beginner question.

The correct way to think about it is:

> **`main()` is a method. When the JVM invokes `main()`, a stack frame is created for that method invocation in the JVM stack of the executing thread.**

So this statement is reasonable:

```text
main() → executes using a stack frame
```

But this statement is misleading:

```text
main() → stored in the stack
```

The method's code is not simply "stored in the stack."

A simplified model is:

```text
Class / Method Information
          ↓
JVM runtime areas

When method executes
          ↓
Stack frame created
          ↓
Local execution data
          ↓
Method returns
          ↓
Stack frame removed
```

---

# 22. What About the Class?

Consider:

```java
class Student {

    String name;

    void study() {
        System.out.println("Studying");
    }
}
```

The `Student` class itself is not an object stored on the stack.

The JVM maintains class-related information in its runtime structures.

When we execute:

```java
Student student = new Student();
```

an object is created at runtime.

Conceptually:

```text
Class definition
      ↓
JVM class-related runtime data

new Student()
      ↓
Student object
      ↓
Heap
```

The easiest way to remember all of this is:

```text
                           │
              ┌────────────┴────────────┐
              │                         │
          Properties                 Methods
              │                         │
              └────────────┬────────────┘
                           │
                       new Class()
                           │
                           ↓
                         OBJECT
                           │

                           │
              ┌────────────┴────────────┐
              ↓                         ↓
          Object State             Object Behavior
                                      │
                                      ↓

                                      │
                                      ↓
                               STACK FRAME
```

And for polymorphism:

```text
METHOD OVERLOADING
───────────────────

Same class
    │
    ├── add(int, int)
    ├── add(int, int, int)
    └── add(double, double)

Different parameter lists
        ↓

```

```text
METHOD OVERRIDING
──────────────────

       Animal
          │
          │ inherits
          ↓
        Dog
          │
          └── sound() overrides Animal.sound()

                 ↓

                 ↓

                 ↓

```

```text
GETTERS & SETTERS
──────────────────

private field
     │
     ├── Getter → read value
     │

```

## Quick Revision

| Concept                 | Meaning                                                                       |
| ----------------------- | ----------------------------------------------------------------------------- |
| Method Overloading      | Same method name with different parameter lists                               |
| Method Overriding       | Subclass provides its own implementation of an inherited instance method      |
| Constructor Overloading | Multiple constructors with different parameter lists                          |
| Class Overloading       | Not a Java concept                                                            |
| Class Overriding        | Not a Java concept                                                            |
| Getter                  | Method used to retrieve a field's value                                       |
| Setter                  | Method used to modify a field's value                                         |
| `private`               | Restricts direct access to a field/member                                     |
| `this`                  | Refers to the current object                                                  |
| Stack                   | Contains per-thread method-execution frames                                   |
| Heap                    | Runtime area where objects and arrays are generally allocated                 |
| `main()`                | Entry point of a standard Java application; its invocation gets a stack frame |
| `new`                   | Creates a new object and invokes its constructor                              |

### One-Line Memory Rule

> **Objects are generally allocated on the heap, while each executing method invocation gets a stack frame on the executing thread's JVM stack.**
