4 Pillars of OOP in Java

The four fundamental pillars of Object-Oriented Programming (OOP) in Java are:

Encapsulation

Inheritance

Polymorphism

Abstraction

These four concepts help us design Java programs using objects, relationships, reusable code, and controlled access to data.

1. Encapsulation
What is Encapsulation?

Encapsulation means wrapping data and the methods that operate on that data inside a class, while controlling how that data can be accessed.

For example:

class BankAccount {

    private double balance;

    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    public double getBalance() {
        return balance;
    }
}


Here:

private double balance;


prevents other classes from directly modifying balance.

Instead, they interact with it through methods:

deposit()
getBalance()


This gives the class control over its own data.

Why do we need Encapsulation?

Protect data from unwanted direct access

Control how data is modified

Keep related data and behavior together

Make code easier to maintain

Reduce unwanted dependencies between classes

2. Inheritance
What is Inheritance?

Inheritance allows one class to acquire properties and behaviors from another class.

The existing class is called the:

Parent class

Superclass

Base class

The new class is called the:

Child class

Subclass

Derived class

Example:

class Animal {

    void eat() {
        System.out.println("Animal is eating");
    }
}

class Dog extends Animal {

    void bark() {
        System.out.println("Dog is barking");
    }
}


Here:

Animal
   ↑
   |
  Dog


Dog inherits from Animal.

Therefore:

Dog d = new Dog();

d.eat();
d.bark();


eat() comes from Animal, while bark() belongs to Dog.

IS-A Relationship

Inheritance represents an IS-A relationship.

Example:

Dog IS-A Animal
Car IS-A Vehicle
Student IS-A Person
Manager IS-A Employee


In Java:

class Animal {
}

class Dog extends Animal {
}


We can say:

Dog IS-A Animal.

This is one of the most important ways to identify whether inheritance makes sense.

HAS-A Relationship

A HAS-A relationship represents composition/aggregation rather than inheritance.

Example:

class Engine {
}

class Car {

    Engine engine;
}


Here:

Car HAS-A Engine


The Car contains an Engine.

We don't write:

class Car extends Engine


because a car is not an engine.

Instead:

class Car {
    Engine engine;
}


So:

IS-A  → usually inheritance
HAS-A → usually composition/aggregation

Simple way to remember
Dog IS-A Animal
Car HAS-A Engine

Why do we use Inheritance?

Inheritance provides:

Code reuse

Parent-child relationships

Method overriding

Runtime polymorphism

Better organization of related classes

Example:

class Vehicle {

    void start() {
        System.out.println("Vehicle started");
    }
}

class Car extends Vehicle {

    void drive() {
        System.out.println("Car is driving");
    }
}


Car can reuse the start() method from Vehicle.

extends Keyword

Java uses the extends keyword for class inheritance.

class Child extends Parent {
}


Example:

class Animal {

    void eat() {
        System.out.println("Eating");
    }
}

class Dog extends Animal {
}


The relationship is:

Animal
  ↑
  |
 Dog

.java File vs .class File

This is an important point when understanding what happens during inheritance.

We write Java source code in .java files.

Example:

Animal.java
Dog.java


When we compile them:

javac Animal.java
javac Dog.java


the Java compiler produces bytecode in .class files:

Animal.class
Dog.class


The JVM works with the compiled .class bytecode, not directly with the .java source code.

So when discussing what happens at runtime, remember:

.java
  ↓
Java Compiler (javac)
  ↓
.class
  ↓
JVM
  ↓
Execution

Important clarification

It is not correct to say:

"For inheritance, we need a .class file instead of a .java file."

Normally, you write the parent and child classes as Java source (.java) files and compile them into .class files.

For example:

Animal.java
    ↓
Animal.class

Dog.java
    ↓
Dog.class


The compiled Dog.class contains the information needed by the JVM to establish that Dog extends Animal.

Types of Class Inheritance in Java

The important class-inheritance structures to understand are:

Single-level inheritance

Multilevel inheritance

Hierarchical inheritance

Multiple inheritance

Java supports the first three through classes.

Java does not support multiple inheritance through classes.

1. Single-Level Inheritance

One parent → one child.

class Animal {

    void eat() {
        System.out.println("Eating");
    }
}

class Dog extends Animal {

    void bark() {
        System.out.println("Barking");
    }
}


Structure:

Animal
   ↑
   |
  Dog


This is called single-level inheritance.

2. Multilevel Inheritance

Inheritance happens across multiple levels.

class Animal {

    void eat() {
        System.out.println("Eating");
    }
}

class Dog extends Animal {

    void bark() {
        System.out.println("Barking");
    }
}

class Puppy extends Dog {

    void play() {
        System.out.println("Playing");
    }
}


Structure:

Animal
   ↑
  Dog
   ↑
 Puppy


Puppy can access inherited members from Dog, and through Dog, members inherited from Animal, subject to Java's access rules.

Example:

Puppy p = new Puppy();

p.eat();
p.bark();
p.play();

3. Hierarchical Inheritance

One parent → multiple children.

class Animal {

    void eat() {
        System.out.println("Eating");
    }
}

class Dog extends Animal {

    void bark() {
        System.out.println("Barking");
    }
}

class Cat extends Animal {

    void meow() {
        System.out.println("Meowing");
    }
}


Structure:

          Animal
         /      \
        ↓        ↓
      Dog       Cat


Both Dog and Cat inherit from Animal.

4. Multiple Inheritance

Multiple inheritance means:

One child class inherits from multiple parent classes.

For example, conceptually:

       Animal       Vehicle
          \          /
           \        /
             Robot


We might imagine:

class Animal {
}

class Vehicle {
}

class Robot extends Animal, Vehicle {
}


But Java does not allow this syntax.

This is invalid:

class Robot extends Animal, Vehicle {
}


A Java class can directly extend only one class.

For example:

class Dog extends Animal {
}


is valid.

But:

class Dog extends Animal, Pet {
}


is not valid Java.

Why Doesn't Java Support Multiple Inheritance Through Classes?

The main reason is ambiguity.

Consider:

class A {

    void show() {
        System.out.println("A");
    }
}

class B {

    void show() {
        System.out.println("B");
    }
}


Suppose Java allowed:

class C extends A, B {
}


Now:

C obj = new C();

obj.show();


Which show() should execute?

A.show()
      OR
B.show()


There is no obvious answer.

This kind of ambiguity is commonly demonstrated using the Diamond Problem.

        A
       / \
      B   C
       \ /
        D


If both B and C inherit something from A, and D inherits from both B and C, the language would need rules to resolve potentially conflicting inherited members.

Java avoids this problem for classes by allowing:

class Child extends Parent


but not:

class Child extends Parent1, Parent2

A Note About Interfaces

Java has another mechanism that can allow a class to have multiple type relationships, using interfaces.

For example, Java allows:

class Robot implements Movable, Printable {
}


This is different from:

class Robot extends Animal, Vehicle {
}


For this lesson, we only need to remember:

Class inheritance:
One class can extend one class.

Interfaces:
A class can implement multiple interfaces.


We will study interfaces separately when they become necessary.

Inheritance and Method Overriding

Inheritance is closely connected to method overriding.

Parent:

class Animal {

    void sound() {
        System.out.println("Animal sound");
    }
}


Child:

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}


Here:

Animal
   ↑
   |
  Dog


Dog inherits from Animal, but provides its own implementation of sound().

This is method overriding.

Method overriding becomes especially important when we study runtime polymorphism.

Access and Inheritance

Not everything in a parent class is inherited or directly accessible in the same way.

For example:

class Parent {

    private int a;
    int b;
    protected int c;
    public int d;
}


A child class cannot directly access the parent's private field:

class Child extends Parent {

    void test() {

        // System.out.println(a); // Not directly accessible

        System.out.println(b);
        System.out.println(c);
        System.out.println(d);
    }
}


private members belong to the parent class's encapsulated state and are not directly accessible from the child.

The exact accessibility of members also depends on access modifiers and package relationships.

Constructor Behavior in Inheritance

Constructors are not inherited.

Suppose:

class Parent {

    Parent() {
        System.out.println("Parent constructor");
    }
}

class Child extends Parent {

    Child() {
        System.out.println("Child constructor");
    }
}


When we create:

Child c = new Child();


the parent constructor executes before the child constructor.

Conceptually:

new Child()
     ↓
Parent constructor
     ↓
Child constructor


This is because the child object must first initialize the parent portion of the object.

super and Inheritance

The super keyword refers to the immediate parent class.

Example:

class Parent {

    int x = 10;
}

class Child extends Parent {

    int x = 20;

    void show() {

        System.out.println(x);
        System.out.println(super.x);
    }
}


Output:

20
10


Here:

x


refers to the child field.

While:

super.x


refers to the parent field.

super can also be used to call the parent constructor:

super();


and the parent version of an overridden method:

super.show();

this vs super
this	super
Refers to current object	Refers to immediate parent part/class
Access current class members	Access parent class members
this.x	super.x
this() calls another constructor in same class	super() calls parent constructor

Example:

class Child extends Parent {

    int x = 20;

    Child() {
        super();
        System.out.println(this.x);
        System.out.println(super.x);
    }
}

Inheritance and Memory

Suppose:

class Animal {

    int age = 10;
}

class Dog extends Animal {

    int legs = 4;
}


Then:

Dog d = new Dog();


creates an object on the heap.

Conceptually, the object contains state belonging to the Dog object, including the inherited Animal state:

Heap
┌─────────────────────┐
│ Dog object          │
│                     │
│ Animal state        │
│ age = 10            │
│                     │
│ Dog state           │
│ legs = 4            │
└─────────────────────┘


The reference variable:

Dog d


is a local variable and, when declared inside a method, is stored in that method's stack frame.

Conceptually:

Stack                  Heap

d ──────────────────→  Dog object
                       ├── age = 10
                       └── legs = 4


This is a simplified model for learning; the JVM's actual implementation details can be more complex.

10. Why Multiple Inheritance Doesn't Work With extends

The major issue is potential ambiguity.

Suppose:

class A {

    void show() {
        System.out.println("A");
    }
}

class B {

    void show() {
        System.out.println("B");
    }
}


If this were allowed:

class C extends A, B {
}


then:

C obj = new C();

obj.show();


would create the question:

Should A.show() execute?
        OR
Should B.show() execute?


This kind of ambiguity is commonly demonstrated using the Diamond Problem.

Java avoids this for class inheritance by allowing only one direct superclass.

11. Constructors Are Not Inherited

If:

class Parent {

    Parent() {
        System.out.println("Parent");
    }
}

class Child extends Parent {

    Child() {
        System.out.println("Child");
    }
}


Creating:

Child c = new Child();


causes the parent constructor to execute before the child constructor.

But the constructor itself is not inherited by the child.

12. super

super refers to the immediate parent class.

It can be used to:

Access parent members

Call a parent method

Call a parent constructor

Example:

super();

super.show();

super.x;
