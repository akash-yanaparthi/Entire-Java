# Everything About Strings in Java

Strings are one of the most commonly used concepts in Java.

We use strings whenever we work with text:

```java
String name = "Rahul";
String city = "Hyderabad";
String message = "Hello World";
```

Before going into the methods, let's understand **what a String actually is and why `String` starts with a capital `S`.**

---

# 1. What Is a String?

A **String** is a sequence of characters.

For example:

```text
"Hello"
```

contains:

```text
H e l l o
```

A String can contain:

* Letters
* Numbers
* Special characters
* Spaces
* Symbols

Examples:

```java
String name = "Rahul";
String phone = "9876543210";
String message = "Hello, Java!";
```

Even though `"9876543210"` contains numbers, it is still a String because it is enclosed in quotes.

---

# 2. Why Is `String` Capitalized?

You may wonder:

```java
String name = "Rahul";
```

Why is it:

```text
String
```

with a capital `S`?

Because **`String` is a class in Java**, not a primitive data type.

Java has primitive types such as:

```text
byte
short
int
long
float
double
char
boolean
```

These start with lowercase letters.

But:

```java
String
```

is a class, so it follows the Java naming convention of using a capital letter for class names.

Conceptually:

```text
Primitive types:

int
char
double
boolean


Classes:

String
Scanner
Student
System
```

For example, when we write:

```java
String name = "Rahul";
```

`String` is the type of the variable `name`.

---

# 3. Is String a Primitive Data Type?

**No.**

`String` is a class.

```java
String name = "Rahul";
```

Here:

```text
String → class/type
name   → reference variable
"Rahul" → String object
```

This is different from:

```java
int age = 20;
```

where `int` is a primitive type.

---

# 4. Why Does String Look Different From Other Objects?

You may have already learned:

```java
Student s = new Student();
```

But for String, we commonly write:

```java
String name = "Rahul";
```

without explicitly using `new`.

This is because Java provides special language support for String literals.

You can also create a String using `new`:

```java
String name = new String("Rahul");
```

But these two forms have important memory differences, which we'll understand through the **String Constant Pool**.

---

# 5. Creating Strings

There are two commonly seen ways.

## Using a String Literal

```java
String name = "Rahul";
```

## Using `new`

```java
String name = new String("Rahul");
```

They both represent the text:

```text
Rahul
```

but the way Java handles their objects in memory is different.

---

# 6. String Constant Pool

The **String Constant Pool** is a special area associated with the JVM's heap that stores interned String literals.

Consider:

```java
String s1 = "Hello";
String s2 = "Hello";
```

Conceptually:

```text
String Constant Pool

        ┌─────────────┐
s1 ───→ │   "Hello"   │
        └─────────────┘
             ↑
             │
s2 ──────────┘
```

Both `s1` and `s2` can refer to the same pooled String object.

Java can reuse the same literal rather than creating another identical pooled object.

---

# 7. Why Does Java Have a String Constant Pool?

Strings are used extremely frequently.

Imagine a program containing:

```java
String s1 = "Java";
String s2 = "Java";
String s3 = "Java";
String s4 = "Java";
```

Creating a separate identical object for every literal would be unnecessary.

Instead, Java can reuse the same pooled String:

```text
s1 ──┐
s2 ──┤
s3 ──┼──→ "Java"
s4 ──┘
```

This is one reason String literals are interned.

---

# 8. `new String()` and Memory

Now consider:

```java
String s1 = "Hello";
String s2 = new String("Hello");
```

The literal `"Hello"` is eligible for the String Constant Pool.

The `new String(...)` expression explicitly creates a new String object.

Conceptually:

```text
STACK

s1 ────────────────┐
                   ↓
              STRING POOL
              ┌─────────┐
              │ "Hello" │
              └─────────┘


s2 ────────────────→ HEAP STRING OBJECT
                     ┌─────────┐
                     │ "Hello" │
                     └─────────┘
```

So although the contents are equal, these can be **different objects**.

---

# 9. `==` vs `.equals()`

This is extremely important with Strings.

Consider:

```java
String s1 = "Hello";
String s2 = "Hello";
```

Now:

```java
System.out.println(s1 == s2);
```

will normally print:

```text
true
```

because both references refer to the same interned literal.

But consider:

```java
String s1 = new String("Hello");
String s2 = new String("Hello");
```

Now:

```java
System.out.println(s1 == s2);
```

prints:

```text
false
```

because they are different String objects.

However:

```java
System.out.println(s1.equals(s2));
```

prints:

```text
true
```

because their contents are equal.

---

# 10. What Does `==` Check?

For object references:

```java
s1 == s2
```

checks whether the two references refer to the **same object**.

It does not perform a content comparison.

---

# 11. What Does `.equals()` Check?

For String:

```java
s1.equals(s2)
```

checks whether the String contents are equal.

Example:

```java
String s1 = "Java";
String s2 = "Java";

System.out.println(s1.equals(s2));
```

Output:

```text
true
```

So remember:

```text
==       → same object/reference
equals() → same String content
```

---

# 12. String Immutability

One of the most important characteristics of String is:

> **String objects are immutable.**

Immutable means:

> Once a String object is created, its contents cannot be changed.

Consider:

```java
String name = "Java";
```

Now:

```java
name = name + " Programming";
```

It may look like we modified `"Java"`.

But we did not.

Instead, a new String is created.

Conceptually:

```text
Before:

name ──→ "Java"


After:

name ──→ "Java Programming"

"Java" remains unchanged.
```

The variable `name` now refers to another String.

---

# 13. Why Is String Immutable?

String immutability provides several benefits, including:

* Safe sharing of String objects
* Useful behavior for String pooling
* Predictable behavior
* Thread-safety of String objects themselves
* Security-related benefits in APIs that use String values

For example:

```java
String username = "Rahul";
```

If Strings could be modified by any reference sharing the same pooled object, changing one reference's String contents could unexpectedly affect another reference.

Immutability prevents that.

---

# 14. Example of Immutability

```java
String s = "Hello";

s.concat(" World");

System.out.println(s);
```

Output:

```text
Hello
```

Why?

Because:

```java
s.concat(" World");
```

creates a new String, but we didn't assign that new String back to `s`.

Correct:

```java
s = s.concat(" World");

System.out.println(s);
```

Output:

```text
Hello World
```

# 46. StringBuffer

`StringBuffer` represents a mutable sequence of characters.

Example:

```java
StringBuffer sb = new StringBuffer("Hello");

sb.append(" World");

System.out.println(sb);
```

Output:

```text
Hello World
```

Unlike String:

```java
String s = "Hello";
s.concat(" World");
```

does not modify the original String.

But:

```java
StringBuffer sb = new StringBuffer("Hello");
sb.append(" World");
```

modifies the same `StringBuffer` object.

---

# 47. Why StringBuffer?

Suppose we repeatedly modify text.

With String:

```java
String s = "A";

s = s + "B";
s = s + "C";
s = s + "D";
```

Strings are immutable, so concatenation can involve creation of new String objects.

A mutable buffer can modify its contents instead:

```java
StringBuffer sb = new StringBuffer("A");

sb.append("B");
sb.append("C");
sb.append("D");
```

# 52. StringBuffer vs StringBuilder

Both are mutable.

The major difference is their synchronization behavior.

| Feature                     | String         | StringBuffer                                     | StringBuilder                                               |
| --------------------------- | -------------- | ------------------------------------------------ | ----------------------------------------------------------- |
| Mutable?                    | No             | Yes                                              | Yes                                                         |
| Can modify same object?     | No             | Yes                                              | Yes                                                         |
| Thread-safe synchronization | Not applicable | Methods are synchronized                         | Not synchronized                                            |
| Typical use                 | Immutable text | Mutable text where synchronized access is needed | Mutable text in typical single-threaded/non-shared contexts |

In many ordinary programs where synchronization isn't required, `StringBuilder` is generally the simpler choice for repeated String modifications.

# 55. `static` in Java

Now let's understand another important Java concept:

```java
static
```

`static` is related to a **class-level member**, rather than a member belonging separately to each object.

It can be used with things such as:

* Variables
* Methods
* Initialization blocks
* Nested classes

We'll focus on static variables and methods.

---

# 56. Instance Variable vs Static Variable

Consider:

```java
class Student {

    String name;
    static String school = "ABC School";
}
```

Here:

```java
String name;
```

is an **instance variable**.

Each Student object has its own `name`.

But:

```java
static String school;
```

is a **static variable**.

There is one class-level variable shared by the class's instances.

Conceptually:

```text
Student Class

static school
      ↓
"ABC School"


Object 1
name → Rahul

Object 2
name → Priya

Object 3
name → Arun
```

---

# 57. Example of Static Variable

```java
class Student {

    String name;
    static String school = "ABC School";
}
```

Create objects:

```java
Student s1 = new Student();
Student s2 = new Student();

s1.name = "Rahul";
s2.name = "Priya";
```

Each object has its own `name`:

```text
s1 → name = Rahul
s2 → name = Priya
```

But both can access the same static variable:

```text
Student.school
      ↓
ABC School
```

---

# 58. Accessing a Static Variable

The preferred way is through the class:

```java
Student.school
```

rather than:

```java
s1.school
```

Although Java permits access through an instance in many cases, using the class name clearly communicates that the member is static/class-level.

---

# 59. Changing a Static Variable

```java
class Student {

    String name;
    static String school = "ABC School";
}
```

Now:

```java
Student.school = "XYZ School";
```

The shared static value changes.

Conceptually:

```text
Student.school
      ↓
"XYZ School"

s1 ─→ name = Rahul
s2 ─→ name = Priya
```

Both objects observe the same static variable.

---

# 60. Why Use Static Variables?

Use a static variable when a value logically belongs to the **class as a whole** rather than separately to every object.

For example:

```java
class Student {

    String name;
    static String school = "ABC School";
}
```

The school can be shared by all Student objects.

Another common example is a counter:

```java
class Student {

    static int count = 0;

    Student() {
        count++;
    }
}
```

Then:

```java
new Student();
new Student();
new Student();

System.out.println(Student.count);
```

Output:

```text
3
```

The static variable keeps the shared count.

---

# 61. Static Method

A method can also be declared `static`.

Example:

```java
class Calculator {

    static int add(int a, int b) {
        return a + b;
    }
}
```

We can call it using the class name:

```java
int result = Calculator.add(10, 20);
```

Output/result:

```text
30
```

We don't need to create a `Calculator` object just to call this static method.

---

# 62. Why Is `main()` Static?

You have already seen:

```java
public static void main(String[] args)
```

Now we can understand part of it.

`main()` is static, so it belongs to the class rather than requiring an instance of that class to invoke it.

Conceptually:

```text
Class
  ↓
main()
  ↓
JVM can invoke the entry-point method
```

The JVM can invoke the static `main` method without first creating an instance of the class.

---

# 63. Static Method and Instance Variable

A static method does not have an implicit `this` reference because it is not invoked on a particular object.

Therefore, it cannot directly access an instance variable.

Example:

```java
class Student {

    String name;

    static void display() {

        // System.out.println(name); // Error
    }
}
```

Why?

Because which object's `name` should it use?

```text
Student Object 1 → Rahul
Student Object 2 → Priya
Student Object 3 → Arun
```

A static method doesn't automatically belong to any one of those objects.

---

# 64. Static Method Can Access Static Members

Example:

```java
class Student {

    static String school = "ABC School";

    static void displaySchool() {
        System.out.println(school);
    }
}
```

Now:

```java
Student.displaySchool();
```

Output:

```text
ABC School
```

Both the variable and method belong to the class level.

---

# 65. Static Method Can Access Instance Members Through an Object

A static method can still work with an instance if you explicitly provide an object/reference.

```java
class Student {

    String name;

    static void display(Student s) {
        System.out.println(s.name);
    }
}
```

Then:

```java
Student student = new Student();

student.name = "Rahul";

Student.display(student);
```

Output:

```text
Rahul
```

The object reference tells the static method which object's `name` to access.

---

# 66. Instance Method vs Static Method

### Instance Method

```java
class Student {

    String name;

    void display() {
        System.out.println(name);
    }
}
```

Call it using an object:

```java
Student s = new Student();
s.display();
```

### Static Method

```java
class Student {

    static void displaySchool() {
        System.out.println("ABC School");
    }
}
```

Call it using the class:

```java
Student.displaySchool();
```

---

# 67. Static vs Instance

| Feature                                 | Instance                    | Static                   |
| --------------------------------------- | --------------------------- | ------------------------ |
| Belongs to                              | Object                      | Class                    |
| Number                                  | One per object/member state | One class-level member   |
| Access                                  | Usually through object      | Preferably through class |
| Can directly access instance variables? | Yes                         | No                       |
| Can directly access static members?     | Yes                         | Yes                      |
| Requires object for invocation/access?  | Generally yes               | No                       |

# 69. Static Does NOT Mean Constant

This is an important distinction.

```java
static int count;
```

does **not** mean the value cannot change.

It means the member is associated with the class.

A constant is commonly declared using:

```java
static final
```

Example:

```java
static final double PI = 3.14159;
```

Here:

```text
static → class-level
final  → cannot be reassigned
```

# 70. `final` vs `static`

### `static`

Means class-level association.

```java
static int count;
```

### `final`

Means the variable cannot be reassigned after initialization.

```java
final int x = 10;
```

### Together

```java
static final int MAX = 100;
```

This represents a class-level value that cannot be reassigned.

# 73. Most Important String Points

Remember these:

### 1. String is a class

```java
String name = "Rahul";
```

`String` is not a primitive type.

### 2. String is immutable

Once a String object is created, its contents cannot be changed.

### 3. String literals are pooled

```java
String a = "Java";
String b = "Java";
```

can refer to the same pooled String.

### 4. `==` and `equals()` are different

```java
==        → reference identity
equals()  → String content
```

### 5. String has many useful methods

```text
length()
charAt()
substring()
equals()
contains()
replace()
split()
concat()
indexOf()
toUpperCase()
toLowerCase()
```

### 6. StringBuffer and StringBuilder are mutable

```text
String        → immutable
StringBuffer  → mutable
StringBuilder → mutable
```

### 7. StringBuffer and StringBuilder are different

```text
StringBuffer  → synchronized
StringBuilder → not synchronized
```

### 8. `static` means class-level association

```java
static int count;
```

is shared at the class level rather than being separate instance state.

### 9. Static methods don't have `this`

Therefore, they cannot directly access instance members.
