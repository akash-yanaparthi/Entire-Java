# Static in Java

The keyword `static` is one of the most important concepts in Java.

Before understanding `static`, remember the difference between:

```text
Class
   ↓
Object
```

An **instance member** belongs to an individual object.

A **static member** belongs to the class itself.

---

# 1. What Does `static` Mean?

When we use the `static` keyword, we are saying:

> This member belongs to the class rather than to a particular object.

For example:

```java
class Student {

    String name;

    static String school = "ABC School";
}
```

Here:

```java
String name;
```

is an **instance variable**.

Every Student object can have a different `name`.

But:

```java
static String school;
```

is a **static variable**.

It is associated with the `Student` class.

---

# 2. Instance Variable vs Static Variable

Consider:

```java
class Student {

    String name;
    int age;

    static String school = "ABC School";
}
```

Now create two objects:

```java
Student s1 = new Student();
Student s2 = new Student();

s1.name = "Rahul";
s1.age = 20;

s2.name = "Priya";
s2.age = 21;
```

We have:

```text
s1
 ├── name → Rahul
 └── age  → 20

s2
 ├── name → Priya
 └── age  → 21
```

Each object has its own:

```text
name
age
```

But:

```text
school
```

is static.

Conceptually:

```text
             Student Class
                  │
                  ↓
          school = "ABC School"
                  ↑
             shared by
              objects
             /       \
            /         \
          s1           s2
       Rahul          Priya
```

---

# 3. Why Do We Need Static?

Imagine every Student has the same school:

```text
Rahul  → ABC School
Priya  → ABC School
Arun   → ABC School
```

If we declare:

```java
String school = "ABC School";
```

then every object gets its own copy of that instance variable.

But if the value logically belongs to the class:

```java
static String school = "ABC School";
```

we can represent it as shared class-level state.

So:

```text
Instance variable
    ↓
Different value for different objects

Static variable
    ↓
Shared class-level value
```

---

# 4. Static Variable

A variable declared with `static` is called a **static variable** or **class variable**.

Example:

```java
class Student {

    String name;

    static String school = "ABC School";
}
```

Here:

```text
name
 ↓
Instance variable

school
 ↓
Static variable
```

---

# 5. Creating Objects

```java
Student s1 = new Student();
Student s2 = new Student();
```

Now:

```java
s1.name = "Rahul";
s2.name = "Priya";
```

We can access the static variable through the class:

```java
System.out.println(Student.school);
```

Output:

```text
ABC School
```

The preferred way to access a static member is through the class name:

```java
Student.school
```

---

# 6. Can We Access Static Variables Through Objects?

Java allows this:

```java
System.out.println(s1.school);
```

and:

```java
System.out.println(s2.school);
```

But this can be misleading.

Since `school` is static, it belongs to the class.

Therefore, prefer:

```java
Student.school
```

rather than:

```java
s1.school
s2.school
```

Think:

```text
Object → instance members

Class → static members
```

---

# 7. Changing a Static Variable

Consider:

```java
class Student {

    String name;

    static String school = "ABC School";
}
```

Now:

```java
Student.school = "XYZ School";
```

The class-level value changes.

So:

```java
System.out.println(Student.school);
```

prints:

```text
XYZ School
```

Objects accessing that static variable will see the updated class-level value.

---

# 8. Complete Example

```java
class Student {

    String name;
    int age;

    static String school = "ABC School";

    void display() {
        System.out.println(name + " " + age + " " + school);
    }
}

public class Main {

    public static void main(String[] args) {

        Student s1 = new Student();
        Student s2 = new Student();

        s1.name = "Rahul";
        s1.age = 20;

        s2.name = "Priya";
        s2.age = 21;

        s1.display();
        s2.display();
    }
}
```

Output:

```text
Rahul 20 ABC School
Priya 21 ABC School
```

Here:

```text
s1.name → Rahul
s1.age  → 20

s2.name → Priya
s2.age  → 21

Student.school → ABC School
```

---

# 9. Static Variables Are Shared

Consider:

```java
class Student {

    String name;

    static int count = 0;

    Student() {
        count++;
    }
}
```

Now:

```java
Student s1 = new Student();
Student s2 = new Student();
Student s3 = new Student();

System.out.println(Student.count);
```

Output:

```text
3
```

Why?

Every time the constructor runs:

```java
count++;
```

The same static variable is incremented.

Conceptually:

```text
Student Class

count = 3
   ↑
   │
 ┌─┴─┐
 │   │
s1  s2  s3
```

The variable isn't separately maintained as:

```text
s1.count
s2.count
s3.count
```

There is one class-level `count`.

---

# 10. Static Methods

We can also make methods static.

Example:

```java
class Calculator {

    static int add(int a, int b) {
        return a + b;
    }
}
```

Now we can call:

```java
int result = Calculator.add(10, 20);

System.out.println(result);
```

Output:

```text
30
```

We don't need:

```java
Calculator c = new Calculator();
```

just to call `add()`.

---

# 11. Why Can We Call a Static Method Without an Object?

Because:

```java
static int add(int a, int b)
```

belongs to the class.

So:

```java
Calculator.add(10, 20);
```

means:

```text
Calculator class
       ↓
   static add()
```

There is no particular Calculator object involved.

---

# 12. Instance Method vs Static Method

### Instance method

```java
class Student {

    String name;

    void display() {
        System.out.println(name);
    }
}
```

We need an object:

```java
Student s = new Student();

s.name = "Rahul";

s.display();
```

Because `display()` is an instance method.

---

### Static method

```java
class Calculator {

    static int add(int a, int b) {
        return a + b;
    }
}
```

We can call:

```java
Calculator.add(10, 20);
```

No object is required.

---

# 13. Static Method and Instance Variables

This is an important rule.

Consider:

```java
class Student {

    String name;

    static void display() {
        System.out.println(name);
    }
}
```

This produces a compilation error.

Why?

Because `name` belongs to an object.

But `display()` is static.

The static method doesn't automatically have a particular Student object to work with.

Which `name` should it use?

```text
Student object 1 → Rahul
Student object 2 → Priya
Student object 3 → Arun
```

There is no particular object associated with the static method.

---

# 14. Static Methods Can Access Static Members

This works:

```java
class Student {

    static String school = "ABC School";

    static void displaySchool() {
        System.out.println(school);
    }
}
```

Call:

```java
Student.displaySchool();
```

Output:

```text
ABC School
```

Both belong to the class:

```text
static variable
      ↓
school

static method
      ↓
displaySchool()
```

---

# 15. Static Method Can Access Instance Data Through an Object

A static method cannot directly access an instance variable.

But we can give it an object.

```java
class Student {

    String name;

    static void display(Student s) {
        System.out.println(s.name);
    }
}
```

Now:

```java
Student s1 = new Student();

s1.name = "Rahul";

Student.display(s1);
```

Output:

```text
Rahul
```

Here the object tells the static method exactly which `name` to access.

---

# 16. Why Is `main()` Static?

You have already seen:

```java
public static void main(String[] args)
```

Now the `static` part makes more sense.

`main()` is the entry point that the JVM invokes.

Because it is static, the JVM can invoke it through the class without first creating an object of that class.

Conceptually:

```text
JVM
 ↓
Main.main()
 ↓
Program starts
```

rather than:

```text
JVM
 ↓
Create Main object
 ↓
Call main()
```

The `main()` method is therefore declared static.

---

# 17. Can We Use `this` Inside a Static Method?

No.

Example:

```java
class Student {

    String name;

    static void display() {
        // System.out.println(this.name);
    }
}
```

This is invalid.

Why?

Because:

```text
this
 ↓
refers to the current object
```

But a static method isn't associated with a particular object invocation.

Therefore, there is no `this` reference available inside a static context.

---

# 18. Static and `this`

Remember:

```text
this
 ↓
Current object

static
 ↓
Class-level
```

So they represent different contexts.

```java
class Student {

    String name;

    void display() {
        System.out.println(this.name);
    }
}
```

This works because `display()` is an instance method.

But:

```java
static void display() {
    System.out.println(this.name);
}
```

doesn't work.

---

# 19. Static Initialization

A class can contain a static initialization block:

```java
class Student {

    static {
        System.out.println("Static block executed");
    }
}
```

A static initialization block is used for class-level initialization.

For example:

```java
class Demo {

    static int x;

    static {
        x = 100;
        System.out.println("Static block");
    }
}
```

When the class is initialized, the static initialization is performed.

---

# 20. Static Block Example

```java
class Demo {

    static {
        System.out.println("Static block executed");
    }

    public static void main(String[] args) {
        System.out.println("Main method executed");
    }
}
```

Output:

```text
Static block executed
Main method executed
```

The class initialization happens before the `main()` body executes.

---

# 21. Multiple Static Blocks

You can have multiple static blocks:

```java
class Demo {

    static {
        System.out.println("Block 1");
    }

    static {
        System.out.println("Block 2");
    }

    public static void main(String[] args) {
        System.out.println("Main");
    }
}
```

They execute in their textual order during class initialization:

```text
Block 1
Block 2
Main
```

---

# 22. Static Does Not Mean Constant

This is a very common misunderstanding.

Consider:

```java
static int count = 10;
```

`static` does **not** mean the value cannot change.

We can do:

```java
count = 20;
```

The value changes.

`static` means:

```text
belongs to the class
```

It does not mean:

```text
cannot change
```

---

# 23. What Does `final` Mean?

`final` is different.

```java
final int x = 10;
```

Once initialized, the variable cannot be reassigned.

So:

```text
static
 ↓
class-level association

final
 ↓
cannot be reassigned
```

---

# 24. `static final`

We can combine them:

```java
class Constants {

    static final double PI = 3.14159;
}
```

Now:

```text
static
 ↓
belongs to class

final
 ↓
cannot be reassigned
```

Access it as:

```java
System.out.println(Constants.PI);
```

This is commonly used for constants.

Java convention usually uses uppercase names for constants:

```java
static final int MAX_SIZE = 100;
```

---

# 25. Instance vs Static — Complete Example

```java
class Employee {

    String name;
    int salary;

    static String company = "ABC";
    static int employeeCount = 0;

    Employee(String name, int salary) {
        this.name = name;
        this.salary = salary;
        employeeCount++;
    }

    void display() {
        System.out.println(name + " " + salary + " " + company);
    }

    static void displayEmployeeCount() {
        System.out.println(employeeCount);
    }
}
```

Create objects:

```java
Employee e1 = new Employee("Rahul", 50000);
Employee e2 = new Employee("Priya", 60000);
```

Now:

```text
e1
 ├── name   → Rahul
 └── salary → 50000

e2
 ├── name   → Priya
 └── salary → 60000


Employee class
 ├── company       → ABC
 └── employeeCount → 2
```

# 26. Memory Perspective

Let's look at the conceptual memory model.

```java
class Student {

    String name;
    static String school = "ABC";
}
```

When we create:

```java
Student s1 = new Student();
Student s2 = new Student();
```

Conceptually:

```text
STACK
────────────────────

s1 ───────────────┐
                  │
s2 ────────────┐  │
               │  │
               ↓  ↓

HEAP
────────────────────

Student Object 1
name → Rahul

Student Object 2
name → Priya


CLASS-LEVEL DATA
────────────────────

Student.school
       ↓
     "ABC"
```

The important conceptual distinction is:

```text
Instance data
    ↓
associated with each object

Static data
    ↓
associated with the class
```

The exact JVM memory layout is more complicated than this simplified diagram, so don't treat it as a literal physical map of every JVM implementation.

---

# 27. Static Variable Lifecycle

Consider:

```java
class Test {

    static int count = 10;
}
```

The static field is associated with the class.

When the class is initialized, its static initialization is performed.

The static field remains available as long as the relevant class remains loaded and its class-level state is reachable according to JVM class-lifecycle rules.

So don't think:

```text
static variable → one copy per object
```

Instead think:

```text
static variable
      ↓
class-level state
```

---

# 28. Static and Objects

A static member does not require an object.

For example:

```java
class MathUtil {

    static int square(int n) {
        return n * n;
    }
}
```

Call:

```java
MathUtil.square(5);
```

No object required.

But an instance method:

```java
class Student {

    void display() {
        System.out.println("Student");
    }
}
```

requires an object:

```java
Student s = new Student();

s.display();
```

---

# 29. Can a Static Method Be Overloaded?

Yes.

Example:

```java
class Calculator {

    static int add(int a, int b) {
        return a + b;
    }

    static int add(int a, int b, int c) {
        return a + b + c;
    }
}
```

Now:

```java
Calculator.add(10, 20);
Calculator.add(10, 20, 30);
```

This is **method overloading**.

Static methods can be overloaded.

---

# 30. Can a Static Method Be Overridden?

This is an important distinction.

Static methods are **not overridden in the same polymorphic way as instance methods**.

If a subclass declares a static method with the same signature, the method is **hidden**, not overridden.

Example:

```java
class Parent {

    static void display() {
        System.out.println("Parent");
    }
}

class Child extends Parent {

    static void display() {
        System.out.println("Child");
    }
}
```

This is called **static method hiding**.

It behaves differently from instance-method overriding.

We will go deeper into this when working with inheritance and polymorphism.

---

# 31. Static Import

Java also supports static imports.

For example:

```java
import static java.lang.Math.PI;
import static java.lang.Math.sqrt;
```

Then we can write:

```java
System.out.println(PI);
System.out.println(sqrt(25));
```

instead of:

```java
System.out.println(Math.PI);
System.out.println(Math.sqrt(25));
```

Static imports are optional and should be used when they improve readability.

---

# 32. Static Nested Classes

Java also allows a nested class to be declared static:

```java
class Outer {

    static class Inner {

        void display() {
            System.out.println("Hello");
        }
    }
}
```

Then:

```java
Outer.Inner obj = new Outer.Inner();

obj.display();
```

This is different from a normal inner class.

Nested classes are a separate topic, so for now the important thing is simply:

> `static` can also be used with nested classes.

# 33. Common Mistakes

### Mistake 1

Thinking:

```text
static = constant
```

Wrong.

```text
static → class-level
final  → cannot be reassigned
```

---

### Mistake 2

Thinking every object has its own static variable.

Wrong.

```text
Instance variable → per object

Static variable → class-level
```

---

### Mistake 3

Trying to use `this` in a static method.

Wrong:

```java
static void display() {
    System.out.println(this.name);
}
```

`this` refers to a current object, while static methods aren't tied to a particular object.

---

### Mistake 4

Trying to directly access an instance variable from a static method.

Wrong:

```java
class Student {

    String name;

    static void display() {
        System.out.println(name);
    }
}
```

You need an object reference.

# 34. Static — Simple Mental Model

Think about a school.

```text
                    SCHOOL
                      │
             ┌────────┴────────┐
             ↓                 ↓
        Rahul Student      Priya Student
             │                 │
        name = Rahul       name = Priya
```

Now suppose both belong to:

```text
ABC School
```

The school can be thought of as class-level information:

```text
Student.school
       ↓
   ABC School
```

The names belong to individual objects:

```text
s1.name → Rahul
s2.name → Priya
```

So:

```text
Instance
   ↓
belongs to each object

Static
   ↓
belongs to the class
```

# 36. The Most Important Difference

Remember this table:

| Feature                              | Instance        | Static           |
| ------------------------------------ | --------------- | ---------------- |
| Belongs to                           | Object          | Class            |
| Separate state per object            | Yes             | No               |
| Requires object                      | Generally yes   | No               |
| Access                               | `object.member` | `Class.member`   |
| Can directly use `this`              | Yes             | No               |
| Can directly access instance members | Yes             | No               |
| Can directly access static members   | Yes             | Yes              |
| Example                              | `name`          | `school`         |
| Method example                       | `display()`     | `displayCount()` |

# 37. Final Example

```java
class Student {

    String name;

    static String school = "ABC School";
    static int count = 0;

    Student(String name) {
        this.name = name;
        count++;
    }

    void display() {
        System.out.println(name + " studies at " + school);
    }

    static void displayCount() {
        System.out.println("Total students: " + count);
    }
}

public class Main {

    public static void main(String[] args) {

        Student s1 = new Student("Rahul");
        Student s2 = new Student("Priya");

        s1.display();
        s2.display();

        Student.displayCount();
    }
}
```

Output:

```text
Rahul studies at ABC School
Priya studies at ABC School
Total students: 2
```

The important thing to observe is:

```text
s1.name
    ↓
Rahul

s2.name
    ↓
Priya


Student.school
       ↓
ABC School


Student.count
       ↓
2
```

So the simplest way to remember `static` is:

> **Instance members belong to objects. Static members belong to the class.**

And one final distinction:

```text
static → class-level
final  → cannot be reassigned
static final → class-level constant
```
